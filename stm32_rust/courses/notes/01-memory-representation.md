# 01 - #[repr] 属性：内存布局控制 (Memory Representation)

在 Rust 中，`repr` 是 **Representation** 的缩写。
`#[repr(...)]` 是一个内置属性，用于控制 `struct`、`enum` 或 `union` 在内存中的**字段顺序保证、对齐规则和底层整数类型**。

---

## 1. 为什么需要控制内存布局？

Rust 默认布局不保证字段声明顺序和具体 Padding。编译器只需要满足 Rust 语义要求，例如字段不重叠、字段地址满足对齐要求等。
1.  **字段顺序不稳定**：不要依赖默认 `repr(Rust)` 的字段偏移。
2.  **自动插入 Padding**：满足硬件和类型对齐要求（如 32 位对齐）。
3.  **枚举布局由编译器决定**：默认枚举的具体内存表示不是稳定 ABI。

**问题**：在嵌入式开发中，硬件寄存器的地址偏移是芯片厂商固定的，网络协议的字节序也是固定的。如果代码依赖了默认布局，你的代码读写寄存器时就可能错位（比如把配置写到了状态寄存器上），导致外设行为异常，严重时触发总线错误或 HardFault。

`#[repr(...)]` 就是告诉编译器：**“按我指定的规则布局，不要随意优化。”**

---

## 2. 常用变体与用途

### 2.1 `#[repr(C)]` —— 强制 C 语言布局
*   **含义**：禁止编译器重排字段，严格按照代码声明的顺序排列，并使用 C 语言的对齐规则。
*   **嵌入式场景**：**映射硬件寄存器 (MMIO)**、FFI 交互（调用 C 函数）。
*   **示例**：
    ```rust
    #[repr(C)]
    struct RCC_Regs {
        cr: u32,      // 0x00
        cfgr: u32,    // 0x04
        _pad: [u32; 4], // 0x08 - 0x14 (占位)
        apb2enr: u32, // 0x18
    }
    ```
    *如果没有这个属性，编译器可能为了优化把 `apb2enr` 挪到 `cfgr` 后面，导致你操作 0x18 地址时实际修改的是 0x08 的寄存器。*

### 2.2 `#[repr(u8)]` / `#[repr(i32)]` —— 指定枚举底层类型
*   **含义**：强制枚举在内存中占用指定的整数大小。
*   **场景**：节省 RAM/Flash，或者枚举值需要与硬件寄存器位域一一对应。
*   **示例**：
    ```rust
    #[repr(u8)]
    enum PinMode {
        Input = 0b00,
        Output10MHz = 0b01,
        Output2MHz = 0b10,
    } // 占用 1 字节，而不是默认的 4 字节
    ```

### 2.3 `#[repr(transparent)]` —— 透明包装 (零开销)
*   **含义**：结构体只能包含一个字段，且保证布局与内部字段**完全一致**。
*   **场景**：新类型模式 (Newtype)，用于增加类型安全但不增加运行时成本。
*   **示例**：
    ```rust
    #[repr(transparent)]
    struct Hertz(u32); 
    // 传参时直接作为 u32 传递，无拷贝无转换
    ```

### 2.4 `#[repr(packed)]` —— 紧凑布局 (危险！)
*   **含义**：降低类型和字段布局使用的对齐要求，并最小化字段间 Padding，但不会改变字段自身的布局。
*   **场景**：解析网络包、解析 FAT 文件系统头。
*   **嵌入式警告**：不要假设非对齐访问在所有 Cortex-M 上都安全。Cortex-M3 对部分普通内存非对齐访问有支持，但 MMIO 寄存器仍应按硬件手册要求自然对齐访问；Rust 的 volatile 读写也要求指针满足类型对齐。
*   **正确做法**：解析 packed 普通内存数据时使用 `ptr::read_unaligned`；访问 MMIO 时不要使用 `repr(packed)` 制造非对齐字段，应保持寄存器自然对齐并使用 `read_volatile/write_volatile`。

## 3. 多语言对照 (Rust vs Zig vs Go)

| 语言 | 机制 | 语义表达 | 嵌入式表现 |
|:---|:---|:---|:---|
| **Rust** | **Attributes** (`#[repr(C)]`) | 编译期指令，附加在类型上 | 极其精准，但需手动处理 `packed` 的对齐访问 |
| **Zig** | **Keywords** (`extern`, `packed`) | 关键字修饰类型 | `extern` 近似 `repr(C)`；`packed struct` 支持按位紧凑布局，语义不同于 Rust 的 `#[repr(packed)]` |
| **Go** | **无显式 repr 机制** | 默认按声明顺序布局，隐式 Padding | 缺少类似 `repr(C)`/`packed` 的精确布局控制；裸机开发通常靠 `unsafe.Pointer` + 偏移计算 |

---

## 4. 最佳实践 (STM32 项目)

1.  **寄存器必加 `#[repr(C)]`**：
    所有映射到物理内存的结构体（如 `RCC_Regs`, `GPIOC_Regs`）都必须加此属性，确保偏移量与 Reference Manual 一致。

2.  **不要对寄存器结构体使用 `#[repr(packed)]`**：
    即使芯片手册里的寄存器连续排列，也不等于可以降低字段对齐。MMIO 访问应保持自然对齐；`repr(packed)` 适合解析外部二进制数据，不适合寄存器块映射。

3.  **验证布局**：
    建议在开发初期使用编译期断言验证偏移量是否符合预期：
    ```rust
    // 确保 apb2enr 确实位于偏移 0x18 处
    const _: () = assert!(
        core::mem::offset_of!(RCC_Regs, apb2enr) == 0x18
    );
    ```
