# 01 - #[repr] 属性：内存布局控制 (Memory Representation)

在 Rust 中，`repr` 是 **Representation** 的缩写。
`#[repr(...)]` 是一个内置属性，用于精确控制 `struct`、`enum` 或 `union` 在内存中的**排列顺序、对齐规则和底层整数类型**。

---

## 1. 为什么需要控制内存布局？

Rust 编译器默认会**自由优化结构体的内存布局**，以提升性能和减小体积。
1.  **重排字段顺序**：把相同大小的字段放在一起，减少 Padding（填充）。
2.  **自动插入 Padding**：满足硬件对齐要求（如 32 位对齐）。
3.  **选择枚举底层类型**：选择能容纳所有变体的最小整数。

**问题**：在嵌入式开发中，硬件寄存器的地址偏移是芯片厂商焊死的，网络协议的字节序是定死的。如果编译器“自作聪明”重排了字段，你的代码读写寄存器时就会错位（比如把配置写到了状态寄存器上），导致 HardFault。

`#[repr(...)]` 就是告诉编译器：**“按我指定的规则布局，不要随意优化。”**

---

## 2. 常用变体与用途

### 2.1 `#[repr(C)]` —— 强制 C 语言布局
*   **含义**：禁止编译器重排字段，严格按照代码声明的顺序排列，并使用 C 语言的对齐规则。
*   **嵌入式场景**：**映射硬件寄存器 (MMIO)**、FFI 交互（调用 C 函数）。
*   **示例**：
    ```rust
    #[repr(C)]
    struct RCC_Regs {
        cr: u32,      // 0x00
        cfgr: u32,    // 0x04
        _pad: [u32; 4], // 0x08 - 0x14 (占位)
        apb2enr: u32, // 0x18
    }
    ```
    *如果没有这个属性，编译器可能为了优化把 `apb2enr` 挪到 `cfgr` 后面，导致你操作 0x18 地址时实际修改的是 0x08 的寄存器。*

### 2.2 `#[repr(u8)]` / `#[repr(i32)]` —— 指定枚举底层类型
*   **含义**：强制枚举在内存中占用指定的整数大小。
*   **场景**：节省 RAM/Flash，或者枚举值需要与硬件寄存器位域一一对应。
*   **示例**：
    ```rust
    #[repr(u8)]
    enum PinMode {
        Input = 0b00,
        Output10MHz = 0b01,
        Output2MHz = 0b10,
    } // 占用 1 字节，而不是默认的 4 字节
    ```

### 2.3 `#[repr(transparent)]` —— 透明包装 (零开销)
*   **含义**：结构体只能包含一个字段，且保证布局与内部字段**完全一致**。
*   **场景**：新类型模式 (Newtype)，用于增加类型安全但不增加运行时成本。
*   **示例**：
    ```rust
    #[repr(transparent)]
    struct Hertz(u32); 
    // 传参时直接作为 u32 传递，无拷贝无转换
    ```

### 2.4 `#[repr(packed)]` —— 紧凑布局 (危险！)
*   **含义**：移除所有 Padding，字段紧挨着排列。
*   **场景**：解析网络包、解析 FAT 文件系统头。
*   **⚠️ 嵌入式警告**：ARM Cortex-M 硬件**不支持**非对齐访问。如果你定义了一个 `#[repr(packed)]` 的结构体并尝试直接读取其中的 `u32` 字段，CPU 会抛出 **HardFault**。
*   **正确做法**：读取时必须使用 `ptr::read_unaligned` 或 `ptr::read_volatile`。

## 3. 多语言对照 (Rust vs Zig vs Go)

| 语言 | 机制 | 语义表达 | 嵌入式表现 |
|:---|:---|:---|:---|
| **Rust** | **Attributes** (`#[repr(C)]`) | 编译期指令，附加在类型上 | 极其精准，但需手动处理 `packed` 的对齐访问 |
| **Zig** | **Keywords** (`extern`, `packed`) | 关键字修饰类型 | `extern` = `repr(C)`，`packed` = `repr(packed)`。语义更直观 |
| **Go** | **无** | 默认固定顺序，隐式 Padding | 无法控制底层布局。裸机开发通常靠 `unsafe.Pointer` + 偏移计算硬解，极易出错 |

## 4. 最佳实践 (STM32 项目)

1.  **寄存器必加 `#[repr(C)]`**：
    所有映射到物理内存的结构体（如 `RCC_Regs`, `GPIOC_Regs`）都必须加此属性，确保偏移量与 Reference Manual 一致。

2.  **绝对不要对寄存器结构体使用 `#[repr(packed)]`**：
    即使芯片手册说寄存器是紧凑的，也不要用。硬件访问需要自然对齐（Alignment），紧凑布局会导致总线错误。

3.  **验证布局**：
    建议在开发初期使用编译期断言验证偏移量是否符合预期：
    ```rust
    // 确保 apb2enr 确实位于偏移 0x18 处
    const _: () = assert!(
        core::mem::offset_of!(RCC_Regs, apb2enr) == 0x18
    );
    ```
