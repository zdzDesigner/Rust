# 10 - Zig Packed Struct 的字边界对齐 (Word Boundary Alignment)

结合之前的讨论，Zig 的 `packed struct(u32)` 在处理**跨字（Cross-word）**数据时有两个关键的对齐规则，这对于映射硬件寄存器至关重要。

---

## 1. 字段跨越 (Spanning)
当单个字段无法完全放入当前 `u32` 的剩余位时，Zig 会自动将其**拆分**并跨越到下一个 `u32` 中。
*   **示例**：在 `packed struct(u32)` 中，`field_a: u20` 后紧接 `field_b: u20`。
    *   `field_a` 占用 Word 0 的 bit 0-19。
    *   `field_b` 占用 Word 0 的 bit 20-31 (12 bits) **以及** Word 1 的 bit 0-7 (8 bits)。
*   **对比 Rust**：Rust 无法定义跨越字节边界的字段。在 Rust 中，一个字段必须完全包含在其分配的字节/字空间内。

## 2. 结构体尺寸对齐 (Struct Size Alignment)
如果结构体中所有字段的总位宽超过了 32 位（例如 40 位），Zig 会自动将整个结构体的尺寸**向上对齐到下一个 32 位边界**（即 64 位/8 字节）。
*   **规则**：`packed struct(T)` 的大小总是 `T` 大小的整数倍。
*   **意义**：这保证了当你在内存中创建该结构体数组时，每个元素都是正确对齐的，符合硬件总线的访问要求。

---

## 3. 与 Rust 的深层对比

| 特性 | Zig `packed struct(u32)` | Rust `#[repr(C)]` |
|:---|:---|:---|
| **字段拆分** | **支持**。字段可跨越 32 位边界 | **不支持**。字段必须完整位于边界内 |
| **尺寸对齐** | 自动对齐到 `u32` 倍数 | 对齐到最大字段的对齐要求 |
| **位流模型** | 视为连续的位流 (Bit Stream) | 视为字节的集合 (Byte Collection) |

**实战影响**：
在 STM32 中，某些寄存器（如 Flash 的选项字节或某些 DMA 配置）的位定义可能刚好跨越 32 位边界。
*   **Zig**：直接定义即可，编译器自动处理拆分和对齐，生成的代码完全符合硬件预期。
*   **Rust**：必须手动拆分为两个 `u32` 结构体，或者使用 `u64` 然后手动处理大小端和位移，极易出错。

*注：本笔记总结了 Zig packed struct 的字边界对齐与跨越规则。*
