# 09 - Zig Packed Struct 自动扩展到多字 (Multi-word Extension)

这是 Zig `packed struct` 机制的另一个关键特性，也是其与 Rust 内存布局模型的重大差异之一。

---

## 1. 自动扩展机制

在 Zig 中，如果你定义 `packed struct(u32)`，并且内部字段的总位宽超过了 32 位，Zig **不会报错**，而是**自动扩展**结构体的大小以容纳所有字段。结构体将占用多个连续的 `u32`（即 64 位、96 位等）。

### 示例
```zig
// 字段总宽度 40 bit，超过 32 bit
const Regs = packed struct(u32) {
    field_a: u20,
    field_b: u20, // 自动延伸到下一个 u32
};
// @sizeOf(Regs) == 8 (即 64 位)
```

**底层行为**：
Zig 编译器会自动计算所需的存储空间。`field_b` 的后 8 位会被放置在第二个 `u32` 的低位。这完全由编译器在编译期处理，对开发者透明。

---

## 2. Rust 的限制

Rust 的结构体**没有**这种自动扩展机制。
1.  **固定大小**：Rust 结构体的大小由其字段决定。如果你定义了两个 `u32` 字段，它就是 8 字节。
2.  **无法隐式跨越**：你无法在 Rust 中定义一个“总位宽 40 位”的结构体。你必须显式地使用 `[u32; 2]` 或者两个 `u32` 字段，并且无法利用编译器自动处理位跨越。
3.  **位域缺失**：由于 Rust 没有 `u20` 这种类型，你甚至无法开始定义这种结构体。

---

## 3. 实战影响

在嵌入式开发中，外设寄存器通常是以 32 位为单位排列的，但单个寄存器内部的位域往往是不规则的。
*   **Zig**：你可以一口气写下一个包含几十个位域的结构体，只要指定底层类型是 `u32`，编译器会自动帮你处理所有的跨越和填充，生成完美的内存映射。
*   **Rust**：你必须极其小心地手动拆分结构体，或者依赖工具生成的复杂代码。如果手动拆分错误，就会导致寄存器访问错位。

**结论**：Zig 的 `packed struct(u32)` 不仅仅是一个类型定义，它实际上是一个**位级内存布局生成器**。它能自动适应硬件的 Word 长度，这是 Rust 目前的 `repr` 属性无法比拟的。

*注：本笔记确认了 Zig packed struct 自动扩展到多字的能力，这是 Rust 结构体不支持的。*
